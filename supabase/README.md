# Supabase

Managed Postgres only — no Supabase Auth, no PostgREST, no `supabase-js` (see
`docs/ARCHITECTURE.md` §1). Migrations are generated by `drizzle-kit` from
`packages/db/src/schema` and land in `migrations/` as plain SQL.

## RLS posture

Every table in the `app` schema is created with row level security enabled and
**no policies** — default deny. This is enforced per-table by the feature
change that creates it (see `add-news-management-system` design.md for an
example).

The API's Postgres role has `BYPASSRLS`. RLS default-deny exists to protect
the database from any future direct-connection tooling (a BI tool, a support
script, a second service) — not from the API itself, which is the only
intended writer per `docs/ARCHITECTURE.md` §1.

## Migrations

- `migrations/` is empty until a feature change supplies SQL via
  `pnpm --filter @siders/db db:generate`.
- Apply with `pnpm --filter @siders/db db:migrate` against `DIRECT_URL`.
