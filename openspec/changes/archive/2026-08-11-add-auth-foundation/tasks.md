## 5. CSRF protection

- [x] 5.1 Add `apps/api/src/lib/csrf.ts`: issue a script-readable CSRF cookie signed with `SESSION_SECRET`, and compare it against the request-header token in constant time
- [x] 5.2 Mount CSRF verification globally in `server.ts`, skipping only safe methods (GET/HEAD/OPTIONS) and requests carrying no session credential — never opt-in per route
- [x] 5.3 Issue a fresh CSRF token whenever a session is established or its credentials are rotated, and stop accepting the previous one — wired at every session-establishment site: `auth.controller.ts`'s `refresh`, `auth.routes.ts`'s staff login, and `google.routes.ts`'s callback all call `setCsrfCookie(res, issued.csrfToken, ...)`. The token is signed **and bound to the session id it was issued for**, which is what retires the previous one: refresh mints a new `app.sessions` row, so the caller's next request carries a new `sid` and a token signed against the old one no longer matches. Still stateless — the comparison is against the `sid` claim `authenticate` already verified, never a DB read. `POST /auth/refresh` is the one exception, where the expired access credential leaves no `sid` to bind against; the signature alone carries it and the response immediately issues a bound token.
- [x] 5.4 Add tests per scenario in `specs/authentication/spec.md`'s CSRF requirement, including the same-site sibling-origin case and the rotation case (`csrf.test.ts`, 11 tests)
